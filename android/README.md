# Meterwise for Android

Native Android app and resizable home-screen widget (Android 8.0+). Version 1.2.0 launches CEL3 Backoffice in a native WebView window without Chrome toolbar or Custom Tabs. Users sign in with their usual credentials and PIN inside the APK; its cookie storage is separate from Chrome. Full console sessions keep the existing server expiry policy (currently 24 hours). After console sign-in, the widget pairs automatically without another login. A five-minute, single-use code is bound to an app-generated verifier (SHA-256 proof of possession); only the originating app can redeem it for a random Meterwise-only device token. The code is consumed with an atomic document revision check. No password is stored or transferred. The device token and pending verifier are encrypted using Android Keystore; the server stores only their hashed identifiers / challenges and an HMAC credential fingerprint in the existing Postgres document store. No database migration is needed. The app and every widget share this one device sign-in.

Device sessions have no time-based expiry. Each data request checks password fingerprints, active staff status, and current Meterwise role access. Changing an owner password (including the configured fallback password), staff password, owner PIN, or server session secret invalidates affected devices. Logout in the Android app revokes that device on the server and clears its cache. Logout inside the native console also clears and revokes its widget session. Widget settings logout clears the native console cookies. Logout in the separate Chrome PWA affects its browser session independently. Offline logout waits for connectivity to ensure server revocation succeeds.

The widget defaults to 4×2 and can resize vertically and horizontally (exact cell dimensions depend on the launcher). A dedicated compact layout keeps month-to-date cost, projection, connected provider accounts, active projects with positive month-to-date costs, daily average, and the number of issue-bearing syncs among the most recent eight visible at two rows. Expanded widgets show the top three provider costs and four recent syncs; the app shows all providers and eight syncs with account, record, and error counts. Calculations match the backoffice dashboard.

The midnight gradient, vector orbital illustration, serif spending figure, teal controls, copper issue accents, and individual metric tiles are native Android resources, including at 4×2. Refresh queues data work directly and shows progress in the widget. Tapping the card opens `/admin/meterwise` directly in the native ConsoleActivity. The app icon opens the full console; the bottom navigation provides Backoffice, Meterwise, Widget settings, and Update. Only HTTPS pages on the configured origin remain in the WebView. External links use normal Android handling. File selection and authenticated downloads are supported; no JavaScript bridge or SSL bypass is exposed.

Backoffice now has a separate `/admin/manifest.webmanifest` (publicly readable for Chrome installation) with a Meterwise shortcut and `/admin` scope, including the existing start URL at `/admin`. The client portal manifest remains scoped to `/portal/`. Older home-screen bookmarks or apps installed using the portal manifest may need to be reinstalled from `/admin` using Chrome's Install app option before Android can target them as a standalone backoffice app.

## Updates from the widget

Version 1.1.0 introduces an Update control alongside Refresh. Existing versions need one manual upgrade to get this control. Subsequent updates are checked, downloaded, and sent to Android's installer directly from the widget, without the main dashboard or backoffice download page. Android requires installation consent and may require allowing Meterwise as an update source once; the app never attempts a silent install.

The updater reads the uncached public `/api/meterwise/android-release` feed, checks the version, downloads only the fixed same-origin `/downloads/meterwise.apk`, and verifies size, SHA-256, package name, strictly newer version, and identical signing certificates before sharing a private-cache file with the system installer. Downloads are capped at 20 MiB. Widget state and sign-in survive an in-place update signed with the original key; `MY_PACKAGE_REPLACED` redraws widgets and resumes refresh. A cancelled/failed install can be retried. Download failure never replaces the existing app.

## Build and publish

1. Install JDK 17 and Android SDK platform 35 / build tools 35.0.0. Set `JAVA_HOME` and `ANDROID_HOME`, or configure `android/local.properties` for your SDK. Local tooling under `.android-tools/` is also recognized by the build script.
2. From the repository root run `node scripts/build-meterwise-android.mjs`. The script uses Gradle 8.9 (local distribution, wrapper, or installed `gradle`). It creates private release signing files on the first build, runs `assembleRelease`, Android lint, and JVM unit tests, then copies the signed APK, checksum, and `meterwise-release.json` to `public/downloads/`.
3. Securely back up `android/meterwise-release.jks` and `android/signing.properties`. These ignored files must be retained for future updates; never commit them. Increment `versionCode` and `versionName` in `app/build.gradle` for updates.
4. Deploy the Next.js application with the generated APK. The signed-in PWA mobile header has an Android app link, and the desktop account menu has Download Android console. `/admin/android` downloads through authenticated `/api/admin/android-download` as `cel3-backoffice.apk`. The package ID and signing key remain unchanged, so installation upgrades the existing Meterwise app while retaining widget state. The Meterwise-specific page remains at `/admin/meterwise/android`. `ADMIN_SESSION_SECRET` must be configured. Use the existing production database and Meterwise configuration.

The compiled backoffice origin defaults to `https://cel3interactive.com`. Set `METERWISE_BACKOFFICE_URL` to another HTTPS origin **before building** if needed. The login, token issuance, and mobile API must all be on that exact origin. The APK contains no API keys or passwords. APKs in `public/downloads` are intentionally public binaries; the app requires authenticated device access for data.

Background updates use WorkManager every 30 minutes, subject to Android power/network scheduling. Manual refresh queues immediate work. Network failures keep the last successful snapshot and display its age; authentication rejection clears it. The APK disables backups and cleartext networking. Automatic widget pairing uses the authenticated native WebView cookie and a one-time PKCE code, never a password. The legacy browser pairing callback remains compatible with earlier releases.

## Validation

Run `node --test scripts/meterwise-widget.test.mjs` for token/revocation, permission, route, and snapshot tests. Run `npx tsc --noEmit` for web types. The build script runs Android lint in addition to APK compilation.

On an Android phone, verify: install, owner sign-in plus PIN, staff access, widget pinning, compact/expanded resizing, refresh without launching an activity, airplane mode cached state, password-change invalidation on refresh, server-side logout, and subsequent sign-in. Verify the PWA download, in-place upgrade, native app launch without browser toolbar, console sign-in and automatic widget connection, file upload/download, external links, keyboard/system insets, and card taps opening native Meterwise. Chrome PWA storage must remain separate from the native console. For the updater, test up-to-date, newer version, unavailable feed, failed download, changed binary/checksum, different signing key, cancelled installer, installation-source permission return, and successful in-place upgrade retaining sign-in. A browser-only session must never authenticate the mobile data API without a device bearer token.
